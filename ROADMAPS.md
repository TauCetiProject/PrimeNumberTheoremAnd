# PNT+ migration into Tau Ceti

Audit: 2026-11-13. Source: [PNT+ `938912b`](https://github.com/AlexKontorovich/PrimeNumberTheoremAnd/tree/938912bbff637bdb18025f0cfd62db3939b63b0a); library: [Tau Ceti `be86813`](https://github.com/TauCetiProject/TauCeti/tree/be86813dc92e6bac8614c2c2dd34572145df09c0); approved specifications: [TauCetiRoadmap `7342e8f`](https://github.com/TauCetiProject/TauCetiRoadmap/tree/7342e8fdd). The dependency's actual pins are in [lake-manifest.json](lake-manifest.json).

This is a migration inventory, not a claim that the refactor or upstream migration is complete. The source inventory contains 233 Lean files: 75 local `Mathlib/` extensions, 26 top-level files, one `Backlund/` file, 126 `IEANTN/` files, four `Unused/` files and one tactic file. Counts describe the inherited source tree; the migration branch currently retains 221 modules, including the root. `README.md`'s upstream notice redirects new IEANTN work to [teorth/IEANTN](https://github.com/teorth/IEANTN); the inherited IEANTN mathematics remains part of this fork's audit.

The Lean 4.36.0-rc2 dependency port uses [TauCetiProject/leancert `eba44d6`](https://github.com/TauCetiProject/leancert/commit/eba44d6ec75ce248b14340547e3fc731bc009f0e), based on upstream `d3e7f68`, with the same exact Mathlib `2ddf59c8` pin as Tau Ceti. It repairs changed set-equality and matrix-continuity APIs, preserves comparison heads during tactic parsing, recognizes arithmetic before speculative max/min reification, and uses the existing reflective checker for two unchanged BKLNW bounds. All nine distinct LeanCert modules directly imported by this fork built successfully (7689 jobs); its compatibility checker confirmed the pin. This downstream dependency repair does not change Tau Ceti's prohibition on metaprogramming or native computation in mathematical contributions.

For complete migration, genuinely additional specifications or extensions are still needed for:

- **Kernel-checked finite certifications:** numerical zero verification, prime-gap/Goldbach tables and rational enclosure certificates, with precise source data, coverage and endpoint guarantees. ZerosOfLFunctions [layer 9](https://github.com/TauCetiProject/TauCetiRoadmap/blob/7342e8fdd/TauCetiRoadmap/ZerosOfLFunctions/README.md#layer-9-certified-zeros) specifies certificate semantics and explicitly computes no zeros. The explicit proposals generally take finite verification as hypotheses. Existing `native_decide` proofs and `TrustedNumerics` admissions cannot enter Tau Ceti unchanged; proving a conditional theorem does not migrate the missing verification.
- **Finite Goldbach transfer and computation:** `IEANTN/Goldbach` includes binary checks and explicit ternary ranges. [CircleMethodThreePrimes #1803](https://github.com/TauCetiProject/TauCetiRoadmap/pull/1803) explicitly excludes binary Goldbach, Helfgott's theorem and all numerical thresholds; it does not cover these finite claims.
- **Erdős problem 392's factorial factorization optimization:** `IEANTN/Erdos392` constructs balanced factorizations and proves asymptotic bounds on the number of factors bounded by `n` or `n²`. Existing logarithmic-factorial/PNT targets supply inputs, not this optimization theorem. A narrow new target must specify both headline conclusions and the balance/score prerequisites.

- **Signed Cesàro Tauberian convergence:** the retained Hardy theorem assumes convergent Cesàro means and `|uₙ|≤A/n`. Newman and logarithmic Tauberian targets have different hypotheses; a narrow additional target is needed.
- **Fejér limits at jumps:** averaging the two one-sided limits needs an explicit target beyond the existing continuous-function uniform and `L¹` approximation targets.
- **Full Riemann–Stieltjes hypotheses:** extend [BanachAlgebras §2.1](https://github.com/TauCetiProject/TauCetiRoadmap/blob/7342e8fdd/TauCetiRoadmap/BanachAlgebras/README.md#21-holomorphic-germs-and-riesz-projections) to arbitrary BV representatives and the source integration-by-parts theorem assuming existence of only one mesh integral. The native variation formula itself already exists; the detailed carrier and endpoint distinctions are below.
